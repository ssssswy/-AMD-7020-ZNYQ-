# TraceGPU v5.1 测试清单

离线回归与构建结果见[修改说明与构建报告](UART连续帧修复说明.md)。下表是实体板验收项目，全部待测。配套应用为 SW51001，硬件为 HW49011。

| 编号 | 操作 | 通过条件 | 状态 |
|---|---|---|---|
| B01 | 使用兼容硬件和新 ELF 启动，保存串口 | 启动标识为 v5.1 / SW51001，LCD、触摸、DMA、GPU 和 AI 初始化正常 | 待测 |
| U01 | 9600、8N1，连续发送 00 至 FF，不增加帧间空闲 | 顺序、数量和末尾 FF 正确，无新增解码帧错误 | 待测 |
| U02 | 115200 下重复 U01，并连续发送多轮 | 每轮完整，数据页翻页与末包一致，采集丢失与解码错误分别记录 | 待测 |
| U03 | 4800 至 921600 各档，N/E/O 校验、1/2 停止位 | 匹配参数时正确；信号源始终发送完整停止位 | 待测 |
| U04 | CH1 至 CH8 逐路停采重解码；四路 UART 实时模式回归 | 通道映射正确，隐藏通道不改变采集配置，实际 PL 实时解码计数单独核对 | 待测 |
| U05 | 只读重解码、首页/末页、HEX/ASCII、筛选和搜索 | 结果和真实字节一致；分页不改变原采样；最后数据可定位波形 | 待测 |
| E01 | 故意翻转校验位、拉低停止槽中心 | 错误类型仍能识别，前后正常帧可恢复 | 待测 |
| E02 | 采集中途停止、触发收尾和清空 | 截断帧标记正确，不拼接跨 GAP 的内容，无新增收尾故障 | 待测 |
| M01 | RS485/Modbus 连续字节、间隔和 CRC 测试 | 有效帧、CRC、帧间空闲及异常恢复符合信号源 | 待测 |
| A01 | 开关 AI 提示，测试规则、CNN、OR、AND | 触发方式与现有配置对应；PS 解码错误与 PL CNN 结果按来源分开 | 待测 |
| H01 | 连续采集并查看异常历史、独立归档 | 不再因本次连续帧错位新增解码错误记录；真实异常可记录并定位 | 待测 |
| R01 | 五点触控、双指缩放/平移、返回采集位置、A/B、us/ms/s | 操作和时间单位正常，字体与 v5.0 显示一致 | 待测 |
| R02 | SPI、I2C、八路逻辑模式切换 | 参数对应协议，解码和收尾正常 | 待测 |
| P01 | 同条件连续输入运行至少 10 分钟 | 保存 VECTOR/PROFILE/GPU_FRAME/AI/HISTORY 日志，核对丢弃增量、积压、FPS，无新增超时 | 待测 |

记录测试人员、日期、信号源固件、通道、实际速率/格式、发送字节数、轮数、持续时间、ELF 身份、日志与截图。v5.0 中已保存的错误历史不会被新程序修改后自动证明无误，复测前应分别保存旧记录并清空本轮历史。
